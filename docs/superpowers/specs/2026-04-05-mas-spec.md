## 1. Objective

Build a **treatment extraction engine** that converts raw financial news into structured, validated causal features for downstream BTC/ETH trading models.

### User Journeys

1. **Ingest & Filter** — SDP refreshes `silver.news_cleaned` every 15 min. The gatekeeper (spaCy NER + sklearn) discards ~95 % irrelevant wire; only crypto-impactful articles (~5 %) enter the agent.
2. **Extract & Validate** — LangGraph agent assigns a discrete treatment class, mechanism, direction, and evidence spans. A deterministic validator checks the extraction against a curated ontology (34 taxonomy entries × 40 whitelist mechanisms).
3. **Harden & Govern (V3)** — Six reliability modules run inline or as batch jobs: uncertainty-aware routing, evidence semantic grounding, DAG-ness auditing, empirical direction verification, confounding detection, and data-driven whitelist governance.

4. **Evaluate & Iterate (Agent Eval)** — Before each deployment, run `mlflow.evaluate()` with AI judges on a curated evaluation set. SME stakeholders review extractions via the Agent Evaluation Review App and provide ground-truth labels that calibrate the judges.

### Success Criteria

| Metric | Target | Measured By |
|--------|--------|-------------|
| Gatekeeper recall / precision | > 0.95 / > 0.80 | pytest + eval set |
| Treatment class L1 accuracy | > 0.70 | Agent Eval: `answer_correctness` judge |
| Evidence grounding rate | > 0.90 | Agent Eval: `groundedness` judge |
| Validation pass rate (accepted / impactful) | > 0.85 | Gold table query |
| Agent Eval: answer relevance | > 0.85 | `relevance` judge |
| Agent Eval: safety | 1.0 (no harmful content) | `safety` judge |
| Aggregate knowledge graph acyclicity | DAG-ness = 0.0 | Nightly batch |
| Average cost per impactful article | ≤ $0.025 | Agent Eval cost metrics |

## 7. Architecture

```
silver.news_cleaned (100 % articles, ~15 min refresh)
        │
  ┌─────▼────────────────────────────────┐
  │  GATEKEEPER (pandas UDF in SDP MV)    │  Stage 1: spaCy NER → short-circuit
  │                                        │  Stage 2: sklearn classifier → confidence
  └─────┬────────────────────────────────┘
        │ is_impactful = True (~5 %)
  ┌─────▼──────────────────────────────────────────────────────────┐
  │  LANGGRAPH AGENT (Model Serving: mas-news-causal)               │
  │                                                                  │
  │  context_retriever → few_shot_retriever (VS top-5)               │
  │       → ★ uncertainty_router (V3-A: fast | standard | careful)   │
  │       → causality_extractor (sonnet LLM + dynamic few-shot)      │
  │       → mechanism_validator (whitelist + ★ evidence grounding B)  │
  └─────┬──────────────────────────────────────────────────────────┘
        │
  gold.news_causal_features (23 fields, Materialized View)
        │
        ├── Delta Sync ──► gold.causal_chains_idx (VS index, feeds back few-shot)
        │
        └── V3 BATCH JOBS ──┬── C. DAG-ness Auditor        (nightly)
                             ├── D. Direction Verifier       (weekly, post TRD-5)
                             ├── E. Confounding Detector     (nightly)
                             └── F. Whitelist Governance     (monthly)
```

### LangGraph Agent — Graph Topology

The agent is a `StateGraph(MASState)` compiled into a Model Serving endpoint (`mas-news-causal`) via Agent Framework (`mlflow.langchain.log_model` → UC registration → Model Serving deploy). **MLflow Tracing** is auto-enabled via `mlflow.langchain.autolog()` — every node invocation, LLM call, and VS query is traced to MLflow Experiment for debugging and cost attribution. The gatekeeper runs **outside** the graph as a pandas UDF in the SDP materialized view; only `is_impactful=True` articles enter.

```
ENTRY → context_retriever → few_shot_retriever → uncertainty_router
          → [fast|standard|careful] → causality_extractor → mechanism_validator → END
```

#### Nodes

| Node | File | Role | Deterministic? | Cost |
|------|------|------|----------------|------|
| `context_retriever` | `nodes.py` | Fetches pre-treatment market state from `gold.dollar_bars` via UC function. **No-op in V1** (returns `None`); activates post TRD-5. | ✅ Yes | ~$0 |
| `few_shot_retriever` | `nodes.py` | Queries VS index `gold.causal_chains_idx` with the article headline. Returns top-5 accepted chains as dynamic few-shot exemplars. Falls back to static examples on cold start. | ✅ Yes | ~$0.001 |
| `uncertainty_router` | `nodes.py` | **V3-A.** Inspects VS similarity scores and result count to decide extraction path (`fast` / `standard` / `careful`). Does NOT call LLM. | ✅ Yes | ~$0 |
| `causality_extractor` | `nodes.py` | Calls sonnet-class LLM with system prompt injecting taxonomy, whitelist, and few-shot exemplars. Prompt length and temperature vary by routing path. On `careful` path: k=3 independent calls + majority vote. | ❌ No | $0.01–0.09 |
| `mechanism_validator` | `nodes.py` | (1) Parses L1 from `treatment_class`. (2) Looks up `(L1, mechanism)` in whitelist. (3) Checks direction ∈ valid set. (4) Verifies evidence spans are normalized substrings of body. (5) **V3-B:** computes `evidence_relevance_score` via embedding cosine similarity. Steps 1–4 reject; step 5 is informational only. | ✅ Yes | ~$0 |

#### Edges

| From | To | Type | Condition |
|------|----|------|-----------|
| `ENTRY` | `context_retriever` | Unconditional | — |
| `context_retriever` | `few_shot_retriever` | Unconditional | — |
| `few_shot_retriever` | `uncertainty_router` | Unconditional | — |
| `uncertainty_router` | `causality_extractor` | **Conditional** | `route_article()` returns path; prompt template + LLM call count set accordingly |
| `causality_extractor` | `mechanism_validator` | Unconditional | — |
| `mechanism_validator` | `END` | Unconditional | — |

#### Routing Conditions (V3 Module A)

| Condition | Path | Prompt | LLM Calls | Latency |
|-----------|------|--------|-----------|---------|
| `top_similarity ≥ 0.85` **and** `n_results ≥ 2` | `fast` | Lean prompt, top-3 few-shot only | 1 | ~1.5 s |
| `0.50 ≤ top_similarity < 0.85` | `standard` | Full prompt, top-5 few-shot | 1 | ~3 s |
| `top_similarity < 0.50` **or** cold start (no VS results) | `careful` | Full prompt + explicit CoT + self-consistency | k=3, majority vote | ~9 s |

#### MASState (LangGraph TypedDict)

| Field | Type | Set By |
|-------|------|--------|
| `story_id`, `headline`, `body`, `published_at` | `str` | Input (SDP) |
| `market_context` | `dict \| None` | `context_retriever` |
| `few_shot_examples` | `list[dict]` | `few_shot_retriever` |
| `retrieval_story_ids` | `list[str]` | `few_shot_retriever` |
| `extraction_path` | `str \| None` | `uncertainty_router` (V3-A) |
| `extraction` | `dict \| None` | `causality_extractor` |
| `validation_status` | `str \| None` | `mechanism_validator` |
| `rejected_mechanism_raw` | `str \| None` | `mechanism_validator` |
| `evidence_relevance_score` | `float \| None` | `mechanism_validator` (V3-B) |
| `output_row` | `dict` | `mechanism_validator` |

### V3 Enhancement Modules

| # | Module | What It Does | Runs | Output |
|---|--------|-------------|------|--------|
| A | **Uncertainty Router** | Routes by VS retrieval similarity: high confidence → fast (1 LLM call), novel/ambiguous → careful (k=3 self-consistency, majority vote) | Per article | `extraction_path` field |
| B | **Evidence Grounding** | Cosine similarity between claim embedding and evidence embedding — scores semantic relevance beyond substring matching | Per article | `evidence_relevance_score` field |
| C | **DAG-ness Auditor** | Builds aggregate adjacency matrix from accepted chains; computes acyclicity score; identifies top cycle-contributing edges | Nightly batch | `gold.dagness_audit_log` |
| D | **Direction Verifier** | Cross-checks LLM-claimed direction against empirical Spearman correlation with market data proxy (Macro treatments only) | Weekly batch | `gold.direction_verification_log` |
| E | **Confounding Detector** | Flags temporal clusters where ≥ 3 distinct treatments target the same asset + direction within a ≤ 4 h window — suggests hidden common cause | Nightly batch | `gold.confounding_audit_log` |
| F | **Whitelist Governance** | Analyses frequently rejected mechanisms, clusters by semantic similarity, surfaces candidates for human approval; maintains a blocklist of forbidden mechanisms | Monthly batch | `gold.mechanism_governance_candidates`, `gold.mechanism_blocklist` |

### Cost Architecture

| Path | Trigger | LLM Calls | Cost |
|------|---------|-----------|------|
| Fast | VS similarity ≥ 0.85 & ≥ 2 matches (~60 %) | 1 (lean prompt) | ~$0.01 |
| Standard | Middle range (~30 %) | 1 (full prompt) | ~$0.03 |
| Careful | VS similarity < 0.50 or cold start (~10 %) | k=3 (self-consistency) | ~$0.09 |

Weighted average: **~$0.022/article** (tracked per-request via Agent Evaluation cost metrics).

### Agent Evaluation — Quality Lifecycle

The system follows an **evaluation-driven development** workflow powered by [Mosaic AI Agent Evaluation](https://docs.databricks.com/en/generative-ai/agent-evaluation/index.html):

| Stage | What Happens | Databricks Primitive |
|-------|-------------|---------------------|
| **1. Curate eval set** | 50+ golden articles with expected treatment class, mechanism, direction, and evidence — stored as `eval_set.json` and versioned in UC as a Delta table | `gold.mas_evaluation_set` |
| **2. Run AI judges** | `mlflow.evaluate(model, data, model_type="databricks-agent")` grades every extraction on 5 built-in criteria | MLflow Experiment run |
| **3. Review App** | Share browser link with domain-expert SMEs to label extractions as correct/incorrect. Feedback stored in UC Delta table, auto-calibrates judges | Agent Evaluation Review App |
| **4. Gate deployment** | PR CI runs `eval.py`; deployment blocked if any judge score < threshold | `uv run python -m agents.eval` |
| **5. Monitor production** | MLflow Tracing + inference table capture every request/response + latency + cost; nightly eval re-run detects drift | MLflow Inference Table + Tracing |

#### AI Judge Metrics

| Judge | Question Answered | Threshold |
|-------|------------------|-----------|
| `answer_correctness` | Does the extracted treatment class match the expected label? | ≥ 0.70 |
| `groundedness` | Is the extraction grounded in the retrieved evidence spans? | ≥ 0.90 |
| `relevance` | Is the extraction on-topic to the article's crypto-market impact? | ≥ 0.85 |
| `safety` | Does the output contain harmful / biased content? | = 1.0 |
| `helpfulness` | Is the structured output useful for downstream ML consumption? | ≥ 0.80 |

All judge scores are logged to MLflow with written rationales. Root-cause analysis uses per-record drill-down to identify systematic failure patterns (e.g., specific treatment classes with low groundedness).

## 8. Output Contract — `gold.news_causal_features`

23 fields total. Fields 1–6 always populated (5 NOT NULL). Fields 7–17 NULL when `is_impactful=False`. Fields 18–20 NULL until TRD-5. Fields 21–23 are V3 additions — all nullable, backward-compatible.

| V3 Field | Type | Source | Description |
|----------|------|--------|-------------|
| `extraction_path` | STRING | Module A | `"fast"` / `"standard"` / `"careful"` |
| `evidence_relevance_score` | DOUBLE | Module B | Cosine similarity [0, 1]; NULL for non-impactful |
| `confounding_cluster_id` | STRING | Module E | Cluster UUID if part of confounded cluster |

**Schema is a contract.** Field renames or removals require explicit approval.

### Agent Evaluation Gate

All 5 AI judge scores must meet thresholds (§7 Agent Evaluation) on the full eval set before any Model Serving deployment. `eval.py` asserts thresholds and fails CI if any judge is below.

### Manual Verification

- Deploy to `trading-signal-gen-dev`, full pipeline refresh, inspect `gold.news_causal_features` row counts and acceptance rate.
- Share Review App link with SMEs; collect ≥ 20 labeled responses to bootstrap judge calibration.
- Confirm `gold.dagness_audit_log` reports `is_dag = true` after initial data load.
- Verify cost profile matches target (~$0.022/article) via MLflow Tracing cost attribution.
- Review `gold.mechanism_governance_candidates` after first monthly run.
